ومع ذلك، كشف الفحص الدقيق عن **7 ثغرات حرجة (Bugs/Defects)** و **4 ديون تقنية** تعيق استقرار الإضافة وتمنع نشرها كمنتج تجاري موثوق، إلى جانب فرص واعدة للتطوير تجعلها الأداة القياسية الأولى في التحريك التسلسلي لـ After Effects.

## 2. المرحلة الأولى: حزمة الإصلاحات الحرجة الفورية (Critical Hotfixes - P0)

> [!IMPORTANT]
> هذه المرحلة يجب تنفيذها كأولوية قصوى لأنها تعالج انهيارات صامتة وأخطاء استقرار تؤثر مباشرة على تجربة المستخدم.

### 2.1 إصلاح مسار تحميل التكوينات في `DataLoader.jsx` [✅ تم التنفيذ - FIX-01]
* **الموقع:** `jsx/core/DataLoader.jsx` (الأسطر 153-176) و `jsx/hostscript.jsx` (الأسطر 582-586).
* **التشخيص:**
  تعتمد الدالة `_getBasePath()` على استدعاء `$.fileName` لتحديد مكان مجلد البيانات `jsx/data/`. عند استدعاء `DataLoader.init()` من داخل `hostscript.jsx`، يُرجع `$.fileName` مسار ملف `hostscript.jsx` (الموجود في المجلد الأب `jsx/`)، فيحاول كود التنقل بالصعود خطوة إضافية للأعلى مما يوجه المسار إلى المجلد الجذري غير الموجود `../data/`. النتيجة: فشل قراءة `controllers.json` بصمت، وتحول جميع استعلامات `DataLoader.getController()` إلى `null`.
* **الحل البرمجي المقترح:**
  1. تخزين مسار الملف ذاتياً لحظة تحميل `DataLoader.jsx` عبر متغير محلي مغلق (Closure).
  2. توفير دعم تمرير المسار الجذري للإضافة مباشرة من `HostService.js` عبر `CSInterface.getSystemPath('extension')`.

```javascript
// في jsx/core/DataLoader.jsx:
(function(scope) {
    var _scriptFolder = (new File($.fileName)).parent.fsName; // مسار jsx/core
    
    scope.DataLoader = {
        _getBasePath: function() {
            var dataFolder = new Folder(_scriptFolder + "/../data/");
            if (dataFolder.exists) {
                return dataFolder.fsName.replace(/\\/g, "/") + "/";
            }
            // مسار بديل مباشر
            return _scriptFolder.replace(/\\/g, "/") + "/../data/";
        },
        // ... باقي الشيفرة
    };
})(this);
```

## 3. المرحلة الثانية: استئصال الديون التقنية وتعزيز الأمان (Code Health & Security - P1)

### 3.1 توحيد مصيدة اختصارات لوحة المفاتيح [✅ تم التنفيذ - REF-01]
* **المشكلة:** توجد مستمعات أحداث `keydown` مستقلة في كل من `main.js` (الأسطر 188-210 لـ Undo/Redo) وفي `keyboard.js` (لباقي الاختصارات).
* **الإجراء:** نقل معالجات `Ctrl+Z` و `Ctrl+Y` بالكامل إلى `keyboard.js` ليصبح المصدر الوحيد (Single Source of Truth) لإدارة مدخلات لوحة المفاتيح.

### 3.2 التشخيص الدقيق والتقييم الحبيبي لموديولات ExtendScript [✅ تم التنفيذ - REF-02]
* **المشكلة:** في `HostService.loadAllJSX()` يتم دمج مسارات 22 موديولاً في استدعاء سلسلة نصية واحدة:
  ```javascript
  var loadScript = '';
  for (var i = 0; i < modules.length; i++) {
      loadScript += '$.evalFile("' + jsxPath + '/' + modules[i] + '");';
  }
  csInterface.evalScript(loadScript, ...);
  ```
  إذا حدث خطأ في بناء الجملة (Syntax Error) في أي ملف، يفشل التحميل بالكامل مع رسالة خطأ عامة `EvalScript error.` دون توضيح الملف المعطوب أو رقم السطر.
* **الإجراء:** كتابة دالة تحميل تتابعية (Sequential Loader) تقيّم كل موديول على حدة وتسجل بدقة اسم الملف وحالته في الكونسول، لتسهيل الصيانة والتطوير.

### 3.3 تطبيق ترويسة سياسة أمان المحتوى (CSP) [✅ تم التنفيذ - SEC-01]
* **المشكلة:** بيئة CEP مفعل فيها وسيط `--mixed-context` و `--enable-nodejs`. غياب سياسة CSP يعرض اللوحة لثغرات أمنية في حال قراءة بيانات غير معقمة.
* **الإجراء:** إضافة ترويسة صارمة في `index.html`:
  ```html
  <meta http-equiv="Content-Security-Policy" content="default-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self' data:; script-src 'self' 'unsafe-eval';">
  ```

### 3.4 معالجة الحقن الآمن لواجهة `SmartChainControls` [✅ تم التنفيذ - REF-03]
* **المشكلة:** في `js/controllers/smart-chain-controls.js:102`، تستدعي دالة `createUI()` دالة `bindEvents()` للبحث عن أزرار بالـ ID (`document.getElementById`) قبل أن تتم إضافة الحاوية إلى شجرة الـ DOM، مما يولد تحذيرات `Button not found`.
* **الإجراء:** فصل إنشاء العناصر عن ربط الأحداث، وتأكيد حقن العنصر في الـ DOM قبل محاولة ربط مستمعات النقر.

## 4. المرحلة الثالثة: تطوير الميزات الحركية المتقدمة وتجربة المستخدم (Features & UX - P2)

### 4.1 السحب والإفلات لإعادة ترتيب السلاسل حركياً (Drag & Drop Reorder)
* **الوصف:** تمكين المستخدم من النقر وسحب أي عنصر داخل خط السلسلة التفاعلي (`chainTimeline`) وسحبه لأعلى أو لأسفل لتغيير ترتيبه في السلسلة حركياً.
* **الأساس البرمجي:** الاستفادة من الخوارزمية الفائقة `ChainInsertion.swapLayers` وربطها بأحداث `DragEvent` في HTML5 لإعادة بناء الروابط في After Effects فور إفلات العنصر.

### 4.2 محرك الفيزياء والمرونة (Spring & Inertial Expressions)
* **الوصف:** إضافة تبديل "Spring / Elastic" بجانب شريط التأخير الزمني.
* **المعادلة الرياضية للتعبير:**
  بدلاً من مجرد تأخير خطي بسيط `time - delay`، يتم حقن معادلة التذبذب المخمد (Damped Harmonic Oscillator):
  $$P(t) = P_{\text{target}} + (P_{\text{start}} - P_{\text{target}}) \cdot e^{-\zeta \omega t} \cdot \cos(\omega \sqrt{1 - \zeta^2} t)$$
  مما يعطي التوابع حركة كرتونية فيزيائية مرنة نابضة بالحياة تشبه حركة الذيل وسلاسل الشخصيات دون الحاجة لبلجنز خارجية.

### 4.3 تصدير واستيراد هياكل الربط الجاهزة (Rig Presets JSON)
* **الوصف:** زر في الواجهة يسمح بحفظ بنية السلسلة الحالية (عدد الحلقات، نقاط الالتقاط، التأخير الزمني، وقيم الدوران) في ملف `.bolasrig` (تنسيق JSON).
* **الفائدة:** تمكين المحرك من استدعاء إعدادات جاهزة (مثل: "طوق ديناميكي"، "ذراع نينجا"، "سلسلة متدلية") وتطبيقها على أي طبقات محددة بنقرة واحدة.

### 4.4 أدلة الربط البصرية في مساحة العمل (Viewport Gizmo Overlay)
* **الوصف:** توليد طبقة دليل مؤقتة (Guide Layer) أو طبقة شكل (Shape Layer) مسماة `_BolasPro_Guides_` ترسم خطوطاً ديناميكية بين نقاط الالتقاط $3 \times 3$ لتوضيح كيفية ترابط الطبقات بصرياً داخل نافذة التكوين، مع إمكانية إخفائها أو حذفها بنقرة زر.

### 4.5 دعم التدويل واللغة العربية (i18n & RTL Support)
* **الوصف:** تعريب واجهة المستخدم بالكامل مع دعم اتجاه الكتابة من اليمين إلى اليسار (RTL) بسلاسة، نظراً لأن أغلب وثائق المشروع مكتوبة باللغة العربية.

## 5. المرحلة الرابعة: الجاهزية للمستقبل والانتقال إلى معيار UXP (Future-Proofing - P3)

أعلنت شركة Adobe رسمياً خطتها لتقاعد منصة **CEP** تدريجياً وإحلال منصة **UXP** الحديثة مكانها.

### خارطة التحول المخططة لـ BolasPro:
1. **عزل منطق الأعمال (Core Logic):** التحقق من أن جميع دوال المعالجة الحسابية والرياضية مستقلة تماماً عن دوال `window` أو `document`.
2. **استبدال CSInterface بـ UXP APIs:** استبدال قنوات `evalScript` البطيئة باستدعاءات `require('photoshop')` أو `require('aftereffects')` المباشرة والمدعومة بمحرك V8 الحديث.
3. **تحويل Manifest:** ترقية `CSXS/manifest.xml` إلى تنسيق `manifest.json` القياسي لـ UXP.
4. **المكاسب المتوقعة:**
   - سرعة تنفيذ أعلى بـ 4 إلى 10 أضعاف في قراءة وكتابة خصائص الطبقات.
   - استهلاك ذاكرة RAM أقل بنسبة 70% مقارنة ببيئة Chromium.
   - توافق كامل ومستقبلي مع كافة إصدارات After Effects القادمة.
